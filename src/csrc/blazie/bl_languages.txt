# The Braille Lite releases the voices and the emulator know: one row per firmware image, keyed by its sha256 (the
# .BNS from 3000h, `length` bytes).  gen_languages.py turns it into bl_languages_table.h, which bl_firmware.c reads
# (its list: blv_import_firmware, blv_state_check, blv_release_*); `python gen_languages.py --check` fails when the
# header is stale (run_tests).  A release is listed only once it was booted through its recipe and its state hashed;
# the row's every column is what the unit itself showed, never a guess.  The list is what the apps can RECOGNISE, never
# what they offer: a voice or an emulator unit is offered only for a release the user imported (or whose firmware is in
# the firmware folder).  Within one voice the newest release comes first: the importers keep the first when a user
# brings two.
#
# Columns, separated by |:
#   id      the release's own name, stable once shipped (a state file or a voice may carry it)
#   model   bl = Braille Lite 2000, bns = Braille 'n Speak 2000, bns640 = Braille 'n Speak 640 (bl_model)
#   tag     its language (BCP 47)
#   voice   the voice it is: a shipped voice's language (english, spanish, german, italian, slovak:
#           bl_firmware.h BLV_FW_*), a new voice's key (blazie_hu: the voice id blazie:blazie_hu, a
#           user's setting, so per language, never per release), or - (the emulator's only)
#   shape   its state recipe (bl_state.h BLV_SHAPE_*): english = three power-ons, the answers early;
#           slow = one long power-on, twelve answers 80 million instructions apart
#   yes     the letter that answers the setup's questions, as the unit asks for it (a-z, computer braille)
#   cp      the unit's DOS code page for its text and file names (850, 852), as read from what it says for its own
#           accented letters; - when not yet read
#   text    the voice's text encoding (bl_voice.h BLV_*): 7bit, 850, 852, 857, 860, 866; hun (the Hungarian
#           unit's letters as its speech rules take them, bl_cphun.h); 852sk (852 with o circumflex sent as its
#           capital: the Slovak and Czech units say nothing for its lower case byte); 852pl, 852hr, 850fr (852 or
#           850 with the letters the unit skips sent as the other case, or as the base letter when it skips both);
#           850dano, 850sv (only those units' own letters from 850); 850es, 850it, 857tr, 860pt, 866ru (the same,
#           for the Spanish, Italian, Turkish, Portuguese and Russian units); 864ar (the Arabic (UAE) unit's 27
#           letters of code page 864, every Arabic letter and form sent as the one it speaks: bl_cp864ar.h,
#           gen_cp864ar.py); - not yet read (the voice then sends plain
#           letters, an accented one as its base letter or ?).  hun ... 850sv were read by sending the unit every
#           byte 80h-FFh in speech-box mode and logging what it said (bl_voice.c PAGES).
#   boot    when the voice presses its boot keys (the speech menu, speech-box mode): fast (from 3M
#           instructions, 1.5M apart: the shipped voices), slow (from 8M, 10M apart: a firmware that boots
#           slower drops early keys and never enters speech-box mode)
#   echo    yes: the unit echoes ^F when a line is done; no: it never does (the voice judges by the chip)
#   speaks  yes: the voice path speaks it (booted, speech-box mode, a sentence said and done); no
#   trillions  how the unit reads a number of 13 digits or more (its own reader stops at 999,999,999,999), as
#           measured through the voice (investigation numbers, 2026-10-16: 1,001,000,000,000 and its billion word):
#           fold = says its billion word for the trillion group ("one billion one billion"), so the voices' number
#           processing sends such a number a digit at a time (bl_numbers.c bl_trillions, blazie.py _trillions);
#           reads = says trillions right (Russian, Korean); digits = already says long numbers digit by digit;
#           - = not measured (a release with no voice)
#   length  the image's length in bytes
#   image   sha256 of the image
#   state   sha256 of the state blv_make_release_state makes from it (MAME's Z180: the same bytes on every platform)
#   name    the unit's name in the emulators' menus (one per release: distinct)
#   vname   the voice's name, its language in English (- for none): a name in its own script (русский) is lost on
#           a voice that cannot read it, which a screen reader's voice list often is (Tomi, 2026-10-12)
#   file    the file name a person is expected to bring (what the import's list shows); the content,
#           not the name, is what the import goes by
#   label   what the import says it found
#
